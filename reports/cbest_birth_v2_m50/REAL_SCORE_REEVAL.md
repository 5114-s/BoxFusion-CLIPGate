# birth-v2-M50 封存输出 real-score 重评（分数敏感性带）

核验日期：2026-09-03（Asia/Shanghai）

## 动机

原始 v2 实验在 score=1.0 强制协议下评测，结论为负增益（−0.18/−0.30/−0.05）并被拒。
本重评检验：同一批 50 个 birth 框在 real-score 协议、不同追加分数下的表现，
以区分"协议/排序伤害"与"词表 FP 真实伤害"。

## 输入与事实

- 封存输出：`results/scannet_cbest_raw_boxer_past3_birth_v2_m50_score05/`（100 场，1,838 框）。
- 前缀 1,788 框带真实分数（0.15–1.0）；50 个 birth 框存储分数为 1.0（占位，源分数未保留，
  与 metadata `birth_count: 50` 一致）。
- 评测器：`scripts/eval_scannet_official100_real_score.sh`（SHA 密封，读取 tuple[2] 为真实分数）。
- 变体构造（纯离线，不改封存资产）：`v2_rescore_prefix_only`（剔除 score==1.0 框，1,788 框）、
  `v2_rescore_birth_s050` / `v2_rescore_birth_s030`（birth 框改赋 0.50 / 0.30）。

## 结果

| official100 real-score | AP15 | AP25 | AP50 | Δ vs Cbest |
|---|---:|---:|---:|---|
| Cbest real-score 基线（参照） | 34.9863 | 31.4140 | 15.6662 | — |
| prefix-only（sanity） | 34.9863 | 31.4140 | 15.6662 | **逐位复现** |
| v2 原始存放（birth=1.0） | 33.6175 | 30.0224 | 14.5397 | −1.37 / −1.39 / −1.13 |
| v2 + birth=0.50 | 35.2552 | 31.6327 | 15.7721 | **+0.27 / +0.22 / +0.11** |
| v2 + birth=0.30 | 35.2546 | 31.6323 | 15.7720 | **+0.27 / +0.22 / +0.11** |

## 判读（按预登记规则）

1. Sanity 通过：prefix-only 逐位复现 Cbest real-score 基线，重评通路有效。
2. **符号翻转成立**：同一批 50 个 birth 框，从"排最顶（score=1.0）"的 −1.37 AP15 变为
   "排低处（0.5 或 0.3）"的 +0.27 AP15。原始 v2 的负增益主要由 score=1.0 协议
   与缺失的 birth 分数模型共同造成，"多帧确认 + 低分追加"本身不是负资产。
3. 排序保护的价值量化：birth=1.0 与 birth=0.5 之差约 **1.6 AP15**——score 列信息量的直接度量，
   为质量感知最终排序提供独立证据。
4. 0.50 与 0.30 结果几乎相同（第 4 位小数级差异）：追加分数只要落在低位，精确取值不敏感；
   真正需要的是与几何质量相关的分数模型，而非手动选值。
5. 增益上限仍受容量约束：50 框中 TP 仅 8/7/5，理论 recall 上限 +0.55/+0.49/+0.35，
   当前实现约兑现一半；+10 级目标需更高召回源与词表对齐门提升 birth precision（v3 方向）。

## 对路线的含义

- Stage 2（延迟确认 birth）重启的硬前提修订为：real-score 协议 + birth 分数模型（质量分）+
  容量与词表对齐（换源时）。
- v2 报告中"birth 不作主精度模块"的结论维持；其"负增益"部分需要按本重评修订。

## 执行契约

- 无管线改动、无重跑推理；全部为封存 pkl 的离线分数改写 + SHA 密封评测器重评。
- GT 仅由评测器在输出冻结后使用（与原始 v2 协议一致）。
