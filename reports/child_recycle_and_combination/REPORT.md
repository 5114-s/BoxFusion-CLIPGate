## 发现清单

1. **child 回收机制成立但天花板有限**：403 框中 39 个 TP（9.7%）@IoU0.15 →
   +1.14/+1.03/+0.44——与预测（2.9 事件/GT 限制三帧确认兑现率）一致。
2. **原生分数追加是灾难（−3.92）**：364 个 FP 以 ~0.55 分数进入中段排序。低分追加
   纪律第三次被独立验证（v2 重评、分数带、本次）。
3. **朴素拼接和 cap6 联合池都负向**：两套 birth 的输出重叠远大于 GT 桶分析
   （6/84）的估计——框级去重砍 33%，剩余仍在双覆盖同一 GT；cap=6 恰好打满时
   混合选择反而变差。
4. **cap=12 让两源共存后全指标登顶**：容量是组合的关键约束，不是确认精度。
5. AP50 最佳仍是 WeDetect 单独（16.5168）——child 几何（单视角 CuTR）在高阈值
   上不如 Boxer 提升的 WeDetect 候选。

**判定：嵌入一致性对 birth 路径无价值（门无用、提分有害）。**
机理：跨视角嵌入一致性度量的是**检测稳定性**，不是**物体有效性**——
持续出现的未标注真物体（词表 FP）同样高度一致，提分把它们一起抬进中段排序。
FDTA 的"实例身份特征"教训在这个位置不适用：身份一致性 ≠ 存在质量。

对质量分路线的含义：候选信号必须与 GT 匹配相关（词表成员资格是最直接候选，
即 v3 的 CLIP-vocab 门思路；或fitness/视角数审计——从未跑过的那项）。
最佳配置维持：**联合池 cap12 @ 均匀 0.10 = 38.2252/34.0239/16.4353**。

**失败机理**：2D 紧致性目标约束不了 3D 深度/尺度——把框拉向各视角图像框的

零深度约束）；且与原生 PFO 的工作条件不同（原生作用于同一演化框的长寿命多视角
证据，非独立 crop）。救援路径：用原生 PFO/CUDA 机器在运行时集成阶段重试，
或改为 3D-3D 一致性目标——均不属离线侧。

联合池 cap12 + 尺寸分桶 = 38.6166 / 34.3168 / 16.4946（相对论文 +9.40/+9.68/+8.45）。**

## 追加：跨检测器共识重排（模块二）—— 破 40（同日夜）

设计：native 框投影到各关键帧，与缓存的 WeDetect-Uni proposal 求最大 2D IoU 作
支持度；**只升不降**：score' = score + α·max(0, support − 0.5)，上限 0.99。
1,695/1,788 个 native 框获得支持（95%），按支持度幅度分层。
漏斗验尸（并行完成）：84 被吞 GT = 33 已挽回 / **40 事件不足三帧** / 4 dedup 残留 /
1 碎片 / 6 几何；针对性修复 child2v（2 帧确认）仅 +28 框且微负（−0.10）——弃用。

在机理上合流：排序信号本身就是在线质量估计器。
